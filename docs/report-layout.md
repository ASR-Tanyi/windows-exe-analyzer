# Reading the report

The report keeps the selected code ahead of module-wide counters and analysis
explanations. All views remain offline and use the same native report facts.

## Where things are

| Area | Contents |
| --- | --- |
| Browse code & data | Symbols, functions, imports, data and search. Collapsed initially at phone widths; `/` opens and focuses search. |
| Report details | Module counts and exception, unwind and TLS metadata shortcuts. |
| Whole function | Compact nonzero metrics, assembly, and one collapsed Function details group for membership, coverage and references. Empty reference groups and single-page pagination are omitted. |
| C-like → Code | Recovered effects, display toggles, exact assembly links, Sources and Trace value actions. |
| C-like → Register flow | Instruction reads and writes, value origins and later uses. |
| C-like → Analysis details | Call assumptions, physical stack locations, cleanup evidence, coverage and analysis limits. |
| Inspector | Contributing assembly for the selected code line, optional value facts and analyst annotations. |

Unknown effects, unavailable transformations and active call assumptions remain
visible above the C-like tabs. Empty call/stack/cleanup groups are omitted. The
unverified Main button is omitted; an analyst-supplied main remains available.
Report schema 2, preview v6, analysis algorithms and exported JSON are unchanged.

## Follow one value

1. In **Code**, click **Trace value** next to a line. This opens the original
   assembly instruction; **Sources** lists every contributor to a combined line.
2. **Reads** shows the values the instruction needs. **Writes** shows its new
   values. Select either to follow it.
3. **Where it comes from** gives the defining instruction and input values.
   **Used later** lists consuming instructions; **Trace instruction** continues
   at one of them. Assembly links open the exact instruction in Whole function.
4. At a branch or loop, a merge selects one incoming value based on the executed
   path. Its rows are alternatives, not values to add together. Follow one input
   at a time to explore loops.

For `mov eax, ecx`, the input is the existing `ecx` value and the output is a new
`eax` value. A later `add eax, 1` reads that output and creates another one.
On x64, these writes appear under the full `rax` family, with an explanation that
the 32-bit write clears the upper 32 bits. A label such as `rax after 0x10e9`
identifies the write. `rax on entry` is unknown incoming state, not proof of a
function argument.

Function-exit observations and values carried into merges are grouped separately
from CPU instruction uses. Raw SSA labels and preservation masks are under
**Technical identity**. Memory and flags remain separate effects; this register
view does not track their values. It always traces the original graph, before
display simplification and cleanup.

Tabs support Left/Right, Home and End keys. The selected tab, instruction and
value survive assembly navigation and Back within the open report. Reloading
starts a new view session; portable labels and call assumptions retain their
existing export/import workflows.

## Validation

Local validation on 2026-10-23–24 used Capstone 5.0.9, LLVM 20 and Playwright 1.57.0:

- 23 CTest targets pass per backend, including the unchanged analysis models.
- 86 Capstone and 13 LLVM C-like browser checks cover tab grouping, model/display
  parity, exact source tracing, merge inputs and exit observations, history,
  keyboard navigation, phone layout, call-assumption import/export and escaping.
- Existing base, data (54), model (18), function (60), CFG (14), strings (36) and
  operand (12) browser checks pass, together with exception metadata (31),
  unwind (32) and TLS (34). All 15 publication tests pass.
- Visual checks use a 1440×1000 desktop and 390×844 phone viewport. For the same
  local optimized `transform_demo`, the first C-like table moves from about
  1,247px to 466px below the document top; Whole function assembly moves from
  1,020px to 557px. The phone C-like table starts at about 605px. These are fixture
  measurements, not layout guarantees for every report.

Recovery reports were regenerated by the native analyzers from the existing
source-known x86/x64 O0/O1 executables. Synthetic metadata/operand/string reports
are generated by their test scripts. With Clang/lld unavailable locally, general
EXE/DLL browser checks use the published native `demo32`, `demo64`, `dll32` and
`dll64` JSON facts in the current report template. Hosted CI recompiles these
fixtures and runs the full backend matrix and semantic oracles.

This is a presentation change. Conservative stack storage roles (M7.3) remain
the next analysis milestone; no additional source-recovery capability is claimed.
